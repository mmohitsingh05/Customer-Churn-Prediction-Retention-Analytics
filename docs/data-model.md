## 1. Source Dataset — `data/raw/customer_churn.csv`

Synthetic, generated by `python/generate_dataset.py`, `N = 5000` rows, `np.random.seed(42)`.

| Column | Type | Description | Generation Logic |
|---|---|---|---|
| `customer_id` | string | `CUST-00001` ... `CUST-05000` | Sequential, zero-padded |
| `age` | int | 18–75 | `np.random.randint(18, 76, N)` |
| `gender` | string | `Male` / `Female` | Uniform random choice |
| `tenure` | int | 1–72 months | `np.random.randint(1, 73, N)` |
| `monthly_charges` | float | 20–150 | `np.random.uniform(20, 150, N)`, rounded 2dp |
| `contract_type` | string | `Month-to-month` (55%), `One year` (25%), `Two year` (20%) | Weighted random choice |
| `support_calls` | int | Poisson-distributed, λ=2.5 | `np.random.poisson(2.5, N)` |
| `internet_service` | string | `DSL` (30%), `Fiber optic` (55%), `No` (15%) | Weighted random choice |
| `payment_method` | string | `Credit card`, `Bank transfer`, `Electronic check`, `Mailed check` | Uniform random choice |
| `total_charges` | float | `monthly_charges * tenure`, rounded 2dp | Derived |
| `churn` | string | `Yes` / `No` | Bernoulli draw from `churn_probability` (see formula below) |

### Churn probability formula (intentional signal, not fully random)

```
churn_probability = 0.08
  + support_calls * 0.035
  + 0.18 if contract_type == "Month-to-month"
  + 0.15 if tenure < 12
  + 0.08 if monthly_charges > 100
  + 0.04 if age > 60
clipped to [0.02, 0.90]
```

This is why Month-to-month, high support calls, short tenure, and high charges must show up as real churn drivers in EDA and feature importance — if they don't, something is broken in the pipeline.

## 2. Cleaned Dataset — `data/processed/customer_churn_clean.csv`

Output of Phase 1 EDA notebook. Adds engineered columns on top of the raw schema:

| Additional Column | Type | Description |
|---|---|---|
| `age_group` | category | Bins: 18-25, 26-35, 36-45, 46-55, 56-65, 66+ |
| `tenure_group` | category | Bins: 0-6, 7-12, 13-24, 25-48, 49-72 months |
| `churn_numeric` | int | `churn == "Yes"` → 1 else 0 |
| `risk_score` | int | Rule-based (0–7): +2 Month-to-month, +2 support_calls≥5, +2 tenure≤12, +1 monthly_charges≥100 |
| `risk_level` | string | `Low` (<3) / `Medium` (3–4) / `High` (≥5) — **rule-based, not ML** |

Data quality guarantees expected after cleaning: zero nulls, zero duplicate `customer_id`, zero duplicate rows.

## 3. Final ML Dataset — `data/processed/customer_churn_ml_predictions.csv`

Output of Phase 2 ML notebook. This is the file loaded into Power BI.

| Column | Type | Notes |
|---|---|---|
| `customer_id` … `churn` | — | Same as raw schema |
| `churn_probability` | float 0–1 | `best_model.predict_proba(X)[:, 1]` |
| `churn_probability_pct` | float 0–100 | `churn_probability * 100`, rounded 2dp |
| `ml_risk_level` | string | `High` (≥0.70), `Medium` (0.40–0.69), `Low` (<0.40) |
| `expected_revenue_risk` | float | `churn_probability * monthly_charges` — model-estimated exposure, NOT confirmed lost revenue |

## 4. PostgreSQL Table — `customers`

```sql
CREATE TABLE customers (
    customer_id VARCHAR(20) PRIMARY KEY,
    age INTEGER,
    gender VARCHAR(20),
    tenure INTEGER,
    monthly_charges NUMERIC(10,2),
    contract_type VARCHAR(50),
    support_calls INTEGER,
    internet_service VARCHAR(50),
    payment_method VARCHAR(50),
    total_charges NUMERIC(12,2),
    churn VARCHAR(10)
);
```

Loaded from `data/processed/customer_churn_clean.csv` via `COPY` or pgAdmin Import/Export.

## 5. ML Feature Set

- **Target:** `churn_target` = 1 if `churn == "Yes"` else 0
- **Numeric features (passthrough):** `age`, `tenure`, `monthly_charges`, `support_calls`
- **Categorical features (one-hot encoded):** `contract_type`, `gender`, `internet_service`, `payment_method`
- **Split:** 80/20 train/test, `random_state=42`, `stratify=y`
- **Models:** `LogisticRegression(max_iter=1000)`, `RandomForestClassifier(n_estimators=300, max_depth=10, random_state=42, class_weight="balanced")`

## 6. Derived Power BI Columns (DAX, calculated columns)

| Column | Logic |
|---|---|
| `Age Group` | SWITCH on `age` bins (same bins as Python `age_group`) |
| `Tenure Group` | SWITCH on `tenure` bins |
| `Charge Group` | Under 50 / 50-99 / 100-124 / 125+ |
| `Churn Flag` | 1/0 from `churn` |
| `High Risk Flag` | 1/0 from `ml_risk_level == "High"` |
| `Retention Segment` | High Risk-High Value / High Risk-Standard Value / Medium Risk / Low Risk (see phase-3 doc §43) |

Keep Python-side and Power BI–side bin boundaries identical — mismatched bins between notebook charts and dashboard charts will produce inconsistent numbers and must be avoided.
